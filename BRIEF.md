# mercurius-antigravity

## Назначение и границы

Модели плана Google Antigravity для агента: официальный клиент `agy` (Antigravity CLI) как одноразовый клиент одного
вызова модели, за интерфейсом Chat Completions. Модуль Меркурия (сабмодуль `services/antigravity/`, профиль compose
`antigravity`), по умолчанию выключен. Цикл агента, инструменты, подтверждения и сжатие остаются у приложения: `agy`
служит только моделью.

**Условия Google такое использование запрещают.** Условия Antigravity (раздел 6) и FAQ называют доступ к сервису
через стороннее программное обеспечение и обёртку `agy` в приложение нарушением, за которое аккаунт может быть
приостановлен или закрыт. Модуль включает владелец экземпляра, понимая этот риск; решение и его основания —
[Google по подписке](../../brief/models.md#google-по-подписке).

Чего модуль не делает: не меняет бинарь `agy`; не читает, не копирует и не пишет файл входа; не ходит к API Google
сам; не принимает ключ Gemini API и облачные учётные данные (для них — провайдеры `gemini:` и `vertex:` приложения);
не меняет аккаунты; не исполняет инструменты; не изображает работу человека за терминалом.

**Состояние.** Код проверен на подставном `agy`. На настоящем `agy` 1.5.18 проверено то, что видно без входа: версия,
флаги, ответы без входа; образ собран на сервере, `/health` и `/v1/models` отвечают, сервис в простое занимает около
33 МБ; ссылка входа и запрос кода работают под псевдотерминалом, неверный код `agy` отвергает. Всё, что требует входа владельца, —
в разделе [Что не проверено](#что-не-проверено).

### HTTP-интерфейс

Всё, кроме `/health`, — за `Authorization: Bearer <ANTIGRAVITY_TOKEN>` (сравнение за постоянное время).

| Маршрут | Что |
|---|---|
| `GET /health` | 200 без входа: CLI найден и не старее минимальной версии; `cli`, `auth` (`login`, `none`), `route`. Иначе 503 |
| `GET /auth/status` | Версия, вход, ждёт ли вход кода |
| `POST /auth/login` | Запускает вход, отдаёт ссылку и `wait_seconds` |
| `POST /auth/code` | Передаёт код ожидающему `agy` |
| `POST /auth/logout` | 501: команды выхода у CLI нет |
| `POST /v1/chat/completions` | Один вызов модели: поток SSE или целый ответ |
| `GET /v1/models` | Модели плана: `id`, `efforts`, `context_window`, `input`, `quota_group` |
| `GET /usage` | Квота плана заново |

Ответ состояния CLI хранится 30 секунд, список моделей — 15 минут (неудачный запрос списка не повторяется минуту).
Тело запроса — до 8 МБ: история идёт текстом, картинки не передаются.

### Запрос

Принимается то, что шлёт приложение: `model`, `messages` (`system`/`developer`, `user`, `assistant` с `tool_calls`,
`tool`; `content` строкой или списком частей), `tools`, `tool_choice` (`auto`, `none`), `reasoning_effort` или
`reasoning.effort`, `stream`, `stream_options`, `temperature`, `max_tokens`, `max_completion_tokens`, `extra_body`,
`n` (только 1), `parallel_tool_calls`. `temperature` и предел ответа принимаются и не действуют: у `agy` их нет.
Незнакомое поле — 400, чтобы ничего не терялось молча. Имя модели — по образцу `^[a-z0-9][a-z0-9.\-]*$`: оно уходит
аргументом. Картинка или видео заменяется пометкой `[media omitted…]`, а не выбрасывается молча. Схема инструмента
приводится к схеме объекта на верхнем уровне: иную `agy` отвергает.

### Модели

Модель, которую `agy` перечисляет как `<база>-low|medium|high|xhigh`, принимает усилие; модель с голым именем — нет.
Приложению отдаются базовые имена; сервис подбирает уровень, который у модели есть: `none` и `minimal` → `low`,
`max` → `xhigh`, отсутствующий уровень — ближайший, при равенстве более сильный. Уровень в имени модели важнее
усилия запроса. Список — `agy models` при выполненном входе; пока CLI не отвечает — закреплённая таблица.

Окно в каталоге — не окно модели, а предел одного сообщения: вся беседа уходит в `agy` одним сообщением, а длинное
сообщение `agy` молча обрезает. Объявлено 60 000 токенов для Gemini и 120 000 для остальных — по наблюдениям
плагинов Hermes, на своей версии не проверено. Так приложение сжимает историю заранее.

### Промпт

`agy` принимает только текст пользователя. Системный текст приложения до первого хода становится телом агента;
за ним — правила инструментов и их список со схемами (сам `agy` схем модели не показывает). Один ход уходит как
есть; история сворачивается в одно сообщение.

Разметка истории несёт метку вызова: `<message-МЕТКА role=…>`, `<tool-call-МЕТКА …>`. Результат инструмента и текст
участника — недоверенные данные и могут содержать что угодно, в том числе закрывающий тег или «системное сообщение».
Метки они не знают, поэтому не могут закончить своё сообщение или начать чужое; модели сказано, что размечают только
теги с меткой. Идентификаторы вызовов и имена попадают в атрибуты только безопасными символами. Образец
(`hermes-plugin-antigravity-agy`) вставляет тексты без экранирования — от этого отступили.

### Один вызов модели

1. Модель и уровень; проверка квоты группы; место в очереди (`ANTIGRAVITY_MAX_CONCURRENT`, ожидание до 120 с).
2. Каталог вызова `antigravity-<16 hex>` (700): `workspace/.agents/agents/mercurius/agent.md` (свой агент:
   `mainAgent: true`, `excludeDefaultComponents: true`, `inheritMcp: false`, инертный MCP `mercurius`), `tools.json`,
   `agy.log`. В рабочем каталоге `agy` нет ничего, кроме агента.
3. `agy --input-format stream-json --output-format stream-json --disable-slash-commands --model <имя> [--effort
   <уровень>] --agent mercurius --log-file <каталог>/agy.log`; один кадр `{"event":"user",…}` в stdin, stdin
   закрывается. На Linux процесс — в своей сессии, чтобы `agy`, его language server и MCP завершались вместе.
4. Поток: `text_delta` отдаётся приложению сразу; первый шаг `call_mcp_tool` нашего сервера с предложенным именем
   заканчивает вызов (`finish_reason: tool_calls`), процесс снимается; `result` со `SUCCESS` — конец с usage
   (`prompt = input + cache_read`, `cached = cache_read`, `reasoning = thinking`). Аргументы инструмента, которые не
   разбираются, — ответ с причиной `length`: приложение спросит снова и ничего не исполнит.
5. Сторож закрыт по умолчанию. Нарушение — любой другой инструмент, чужой сервер, непредложенное имя, шаг
   незнакомого вида (известны `user_input`, `agent_response`, `tool`, `error_message`), имя агента в `init`, отличное
   от нашего, или строка журнала «falling back to default». Журнал смотрится при `init`, перед первым словом
   ответа, перед вызовом инструмента и при `result`: текст агента по умолчанию приложению не уходит. Свой вызов в
   состоянии не `ACTIVE` ждёт: его аргументы могут быть неполны. Вызов без аргументов у инструмента с обязательными
   параметрами — ответ с причиной `length`. Нарушение снимает процесс, вызов кончается ошибкой.
   Если файл агента не записался, `agy` не запускается вовсе.
6. После вызова: группа процессов снята (и когда `agy` уже завершился сам — его помощники могут пережить его),
   запись беседы `agy` (`conversations/<id>*`) удалена, каталог вызова удалён. Короткие запуски (`--version`,
   `models`, квота) и вход идут так же — своей сессией со снятием группы.

### Ошибки

Тело ошибки — `{"error": {"message", "type", "code", "resets_at"?}}`.

| Признак в словах `agy` | Статус | `type` |
|---|---|---|
| «verify your account», «terms of service» | 403 | `account_action_required` |
| нет входа («not logged into antigravity», «authentication required») | 401 | `authentication_error` |
| «credits balance is too low», «billing cap» | 402 | `billing_error` |
| `RESOURCE_EXHAUSTED`, «quota», 429 | 429 с `resets_at` и `retry-after` | `rate_limit_error` |
| «No capacity available», 503 | 529 | `overloaded_error` |
| неверная модель | 400 | `invalid_request_error` |
| нарушение | 422 | `tool_violation` |
| тишина дольше `ANTIGRAVITY_IDLE_SECONDS` | 504 | `timeout_error` |
| `agy` не запустился | 503 | `api_error` |
| нет места в очереди | 529 | `overloaded_error` |
| `agy` кончил без ответа | 502 | `api_error` |

Вид ошибки решают слова самой ошибки (`result.error` и stderr). Журнал `agy` длинный и упоминает что угодно, поэтому
из него читается один признак — `RESOURCE_EXHAUSTED`; иначе обычный сбой со словами об условиях в журнале снял бы
провайдера как «Google просит действовать». Нарушение идёт статусом 422, который клиент не повторяет: второй
процесс сделал бы то же. В тексте отказа по квоте
нет слов «quota exceeded»: клиент приложения читает их как «кончились деньги». Ошибка до первого события — ответ
HTTP; после него — событие с `error` в потоке.

### Квота

`agy -p /usage --output-format json` в пустом каталоге, 15 секунд; в ответе ищется первый вложенный объект со
списком `groups`. Группа — имя и окна (`window`, доля остатка, время сброса). Ответ хранится минуту, спрашивает
один вызов за раз; при сбое служит прежний ответ с пометкой `stale`, и молчащий CLI не спрашивается заново минуту. Группа модели: `gemini*` — «Gemini Models»,
остальные — «Claude and GPT models». Исчерпанное окно закрывает модели своей группы, а не всю подписку: вызов
отклоняется до запуска `agy`. Пока `agy` молчит, его журнал просматривается на `RESOURCE_EXHAUSTED`: сам `agy`
повторяет 429 молча около двух минут. Время «Resets in 1h49m22s» из журнала закрывает группу до этого срока.

### Вход

Спрошенный в режиме печати без входа, `agy` печатает ссылку Google и ждёт код, который владелец получает после
входа в своём браузере. Ссылку он предлагает, только когда его ввод — терминал: через обычный канал отвечает
«authentication required» без ссылки (проверено на 1.5.18). Поэтому один этот шаг — вход, никогда не вызов модели —
идёт под `script`, который даёт дочернему процессу терминал и передаёт ему код. Вход, который никто не закончил,
снимается через минуту; новый вход не трогает чужой процесс. Сервис передаёт ссылку и код и не хранит их. Один вход
за раз; `agy` ждёт код 60 секунд. «Вход есть» — файл входа в домашнем каталоге `agy` существует и не пуст;
содержимое не читается. Команды выхода у CLI нет: владелец выходит в настройках аккаунта Google или удаляет каталог
данных модуля.

### Среда agy

Образ — `php:8.2-cli-bookworm` и один бинарь `agy` (268 МБ, связан только с glibc), скачанный при сборке с проверкой
sha512; в реестр образов бинарь не выкладывается. Пользователь `antigravity` (uid 10060) без оболочки.

Окружение дочернего процесса собирается из списка, а не копируется: `PATH`, локаль, `TZ`, временные каталоги,
сертификаты; `HOME` — том входа; `AGY_CLI_DISABLE_AUTO_UPDATE=true`; прокси сервиса и `NO_PROXY` для loopback (там
`agy` говорит со своим language server). Переменных приложения и токена модуля в нём нет. Унаследованные
`GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_CLOUD_PROJECT`,
`GOOGLE_GENAI_USE_VERTEXAI` останавливают сервис: `agy` вошёл бы по ним и считал расход по прайсу API вместо плана.

Чистая среда убирает лишнее и экономит память, но того, что `agy` работает внутри приложения, не скрывает и скрывать
не призвана: это видно по самим запросам. Терминал при вызовах модели не создаётся: режим stream-json идёт через
каналы. Псевдотерминал есть только у шага входа — без него `agy` не показывает ссылку.

Журнал сервиса — строки JSON в stderr: отказ прокси с именем хоста, вид нарушения, сбой запуска. Промпты, коды и
токены в журнал не пишутся.

### Сеть

Маршрут один на всё: `ANTIGRAVITY_PROXY=direct` — напрямую; иначе `VLESS_URI`, иначе `ANTIGRAVITY_PROXY`, иначе
напрямую. Адрес API в `agy` не подменить, поэтому шлюза перед API нет: при маршруте ребёнок получает `HTTPS_PROXY` на
loopback-прокси сервиса, который принимает только CONNECT на порт 443 к хостам Google и открывает туннель через
маршрут. TLS кончается у Google. Хосты — точным списком: `accounts.google.com`, `oauth2.googleapis.com`,
`www.googleapis.com`, `cloudcode-pa.googleapis.com`, `daily-cloudcode-pa.googleapis.com`, `antigravity.google`,
`www.antigravity.google`. Целые домены Google не открыты: там лежат чужие бакеты и документы. Хост, которого в
списке нет, получает отказ с записью имени в журнал; `ANTIGRAVITY_EGRESS_HOSTS` добавляет точные имена через
запятую — так список дополняется после первого настоящего входа. Прокси — маршрут, а не граница: процесс, который
не смотрит на `HTTPS_PROXY`, по-прежнему имеет сеть контейнера.

## Решения

- **Один процесс на вызов,** а не долгоживущий `agy` и не `--conversation`: в беседе `agy` оставались бы результаты
  инструментов, и история расходилась бы с историей приложения.
- **Интерфейс — Chat Completions:** ответ `agy` — текст, один вызов инструмента и usage; общие части клиента
  приложения работают без изображения чужого API.
- **Один вызов инструмента за ответ:** `agy` выполняет вызовы по очереди, виден первый.
- **Никаких своих повторов** поверх повторов `agy`; малый предел одновременности; очередь вместо всплеска.
- **Прогрев не сделан:** запасной процесс стоит около 400 МБ; вернуться после замера.
- **Картинки и видео не передаются:** нужен файл и встроенное чтение `agy`, а значит правило для сторожа; отдельная
  задача.

## Что не проверено

**До включения модуля обязательно:** разворачивает ли `agy` `@путь` в тексте пользователя. Текст участника и
результат инструмента уходят в сообщение как есть; если `agy` подставляет файлы по `@пути`, строка на чужой
веб-странице втянула бы в промпт файл входа. Проверяется канарейкой сразу после входа; до проверки модуль на
экземпляре с недоверенными источниками не включать.

Нужен вход владельца: принимается ли настоящий код и как называется файл входа (сервис ищет
`jetski-standalone-oauth-token` и `antigravity-oauth-token`); полный список хостов; события успешного хода и вызова инструмента на своей
версии; грузится ли свой агент и каков маркер отката; `agy models` и уровни усилия; верна ли команда `/usage` и
формат квоты; тексты ошибок; предел одного сообщения; разворачивает ли `agy` `@путь`; память процесса; настоящий
список хостов; работа через прокси. Выбор между stream-json и ACP (`agy acp` есть в том же бинаре) тоже ждёт этого.

## Обновление agy

Сменить `AGY_VERSION`, `AGY_BUILD` и суммы в `Dockerfile` (манифест —
`https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/linux_amd64.json`) → собрать на
сервере → сверить события stream-json с подставным `agy` → свой агент грузится (нет «falling back») → квота
разбирается → `@путь` не разворачивается → выкладка. Минимальная версия — `ANTIGRAVITY_MIN_VERSION`, её называет
`/health`.

## Проверки

`composer check` — PHPUnit, PHPStan (max), Psalm (уровень 1) на подставном `agy`, без входа и без сети; то же в
GitHub Actions на PHP 8.2.
